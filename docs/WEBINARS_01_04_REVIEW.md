## Проверка на противоречия
- Все документы используют **синтетический v3 7 000 / 3 776 warm-up**; старые метрики не смешиваются с новым набором.
- **CatBoost не объявлен победителем**: его API — прототип, а итоговый выбор кандидата будет зафиксирован по validation.
- В коде **нет** реального банка, feature store, production-canary, автоматического rollback.
- Схема В02 явно помечает внешние проектируемые компоненты.
- В03 фиксирует **текущее**, а не желаемое поведение API, включая необработанные ошибки загрузки артефакта.
- В04 не выдаёт существование файлов конфигурации за подтверждённую эксплуатацию.

## Внешние действия для формальной сдачи
1. В01: получить точное задание, если преподаватель использовал отдельный шаблон.
2. В02: перенести схему в Holst либо приложить скриншот; отправить ссылку/объяснение.
3. В03: разместить контракт в документе/области команды и отправить примеры.
4. В04: сделать копию шаблона в Google Docs, указать название команды, отправить ссылку и следующий шаг.

**Итог:** содержательная работа по В01–В04 оформлена в репозитории. Официальная сдача и реальные эксплуатационные проверки — отдельные неподтверждённые факты.


## Актуальная модель проекта (для защиты)

Выбрана **ExtraTrees v4**: 200 деревьев, глубина 4, минимум 6 объектов в листе; 13 исходных + 7 engineered признаков. Validation PR-AUC **0,342852**, ROC-AUC **0,803479** на синтетическом v3. Выбор по максимальному validation PR-AUC в [32-конфигурационном скрининге](../docs/WEBINAR05_32_EXPERIMENTS.md); дополнительный поиск (30+30 trials, 50–100 деревьев) не охватывал выбранные 200 деревьев. [ZIP модели](../extratrees-v4-artifact.zip) в `main`. **Загрузка v4 в FastAPI и XAI пока не реализованы/не подтверждены**. Legacy CatBoost/Blend в старых разделах — история экспериментов, не финальный выбор.
