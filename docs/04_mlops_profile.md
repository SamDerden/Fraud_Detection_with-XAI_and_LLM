# Вебинар 4 — MLOps-профиль учебной команды

**Кейс:** учебная команда, разрабатывающая антифрод-скоринг для условного банка. **Тип организации для практики:** стартап/небольшая проектная команда, **не** реально действующий крупный банк. Учебный проект не подключён к банковскому трафику.

> Методичка требует честно описывать **текущее**, а не желаемое состояние. Поэтому ниже различаются «реализовано», «проверено» и «спроектировано».

| Блок | Текущее состояние | Что требуется улучшить |
|---|---|---|
| **1. Задача и пользователь** | Риск-скоринг синтетической транзакции для демонстрации и возможной ручной проверки; вызывающая система — API-клиент, потенциальный пользователь — аналитик антифрода. Реальных банковских пользователей нет. | Определить бизнес-стоимость FN/FP и SLA с заказчиком |
| **2. Данные** | Синтетический v3: 7 000 размеченных операций, отдельно 3 776 warm-up, 220 пользователей; 5 000 train / 1 000 validation / 1 000 test. Проверены базовые логические ограничения и статистическая связь новых устройств с меткой. | Автоматически и независимо пересчитывать исторические признаки; версионировать датасет |
| **3. Модель / логика** | Сравнены RF, CatBoost, LightGBM и ансамбль. По validation PR-AUC лучший ансамбль (0.25779), по test PR-AUC — LightGBM (0.25524). Это не основание выбирать по test. API-артефакт CatBoost — технический прототип, **не** утверждённая финальная модель. SHAP реализован для CatBoost. | Формально выбрать кандидата по validation и ограничениям, затем унифицировать модель/SHAP/API |
| **4. Эксперименты** | Есть диагностическое сравнение моделей и скрипты для MLflow; **подтверждённого MLflow run на v3 нет**. | Зафиксировать seed, версию данных, параметры, метрики и артефакты в MLflow |
| **5. Проверки качества** | Есть тесты API, модели, артефакта и SHAP; часть CI-запусков проходила, но результат последней версии требует проверки. E2E на окончательной модели v3 не подтверждён. | Единый зелёный CI + независимый E2E + тесты ошибок |
| **6. Запуск и обновление** | Dockerfile и Compose есть; реального production, shadow, canary, blue-green и автоматического rollback **нет**. | Подтвердить Docker smoke; затем описать безопасную процедуру релиза |
| **7. Мониторинг** | Код Prometheus HTTP-метрик, конфигурация и правила алертов есть. Отсутствует реальный поток с подтверждёнными метками для оценки precision/recall онлайн. | Подтвердить сбор метрик и настроить анализ дрейфа и delayed labels |
| **8. Зрелость** | **Уровень 0 с элементами уровня 1**: отдельные автоматизированные тесты и CI есть, но воспроизводимый полный ML-пайплайн и эксплуатация модели не подтверждены. Это не уровень 2 и не полноценный уровень 1. | Зафиксировать критерии перехода к уровню 1 |
| **9. Один следующий шаг** | **Воспроизводимый MLflow-эксперимент на принятом v3**, включая версии данных, параметры, метрики, validation-выбор и экспорт модели. | Без этого через 6–12 месяцев нельзя будет доказать, почему выбрали конкретную модель и как повторить результат |

## Обоснование зрелости
**Уровень 0 с элементами 1.** Код, тесты, CI, конфигурация Docker и мониторинга уже существуют. Однако нельзя утверждать, что автоматизирована сквозная цепочка «версионированные данные → эксперимент → модель → деплой → наблюдение → переобучение». Ранее в отчёте ошибочно говорилось о действующем canary и подтверждённом MLflow — это были проектные намерения. Уровень 1 станет обоснованным после повторяемого ML-пайплайна с зарегистрированными артефактами и автоматическими проверками.

## Roadmap на 6 месяцев (дополнение для домашнего задания, не обязательная часть практики)
| Период | Измеримый результат |
|---|---|
| Месяц 1 | v3 зарегистрирован, MLflow run + версия данных + воспроизводимый выбор модели |
| Месяц 2 | Итоговая модель и XAI работают в API; E2E-тесты и CI зелёные |
| Месяц 3 | Docker Compose smoke, метрики и алерты подтверждены |

| Месяц 6 | Полный демонстрационный релиз, документация, защита и повторный аудит |

## Актуализация выбора модели — ExtraTrees v4 (21.11.2026)

**Для защиты выбрана ExtraTrees v4**, 13 исходных + 7 производных признаков; validation PR-AUC **0,342852**, ROC-AUC **0,803479** на синтетическом v3. В 32-конфигурационном скрининге это лучший validation PR-AUC. Параметры: `n_estimators=200, max_depth=4, min_samples_leaf=6, random_state=42`. Артефакт [extratrees-v4-artifact.zip](../extratrees-v4-artifact.zip) опубликован. [Методика, все 32 результата и ограничения](WEBINAR05_32_EXPERIMENTS.md). **Сервер и XAI пока работают по legacy-контракту; v4 ещё не подключена.** Упоминания CatBoost/Blend выше относятся к предыдущему этапу проекта, не к финальному выбору. Отдельный test для v4 и калибровка порога не подтверждены.
