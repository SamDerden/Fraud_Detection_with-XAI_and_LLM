# Вебинар 8 — unit и integration тесты с mock

**Цель методички:** проверить код вокруг модели, не её точность. Практика включает пять unit-тестов `clean_text` (HTML, пробелы, края, регистр, пустая строка) и пять mock/integration сценариев (три решения, контракт, отказ модели); изучение GitHub Actions и короткий вывод.

## Реализованная учебная проверка
`tests/test_webinar08_components.py` содержит:
- **5 unit**: `clean_text` удаляет HTML, нормализует пробелы, регистр, обрабатывает пустой ввод;
- **3 mock-решения**: управляемые scores 0.1, 0.5, 0.9 и проверка вызова модели;
- **1 mock-отказ**: модель выбрасывает RuntimeError, тест проверяет распространение ошибки;
- **2 контрактных**: неположительная сумма и недопустимый score.

**Локальный запуск:** `pytest -q tests/test_webinar08_components.py` → **11 passed** (20.11.2026). Вместе с В07 при `ANTIFRAUD_V3_CSV` → **17 passed**.

## Важное ограничение
Это **самостоятельный учебный mock-сервис**, а не утверждение о том, что настоящий FastAPI обрабатывает сбой модели корректно. В текущем `src/antifraud/app.py` отсутствие/повреждение артефакта может привести к необработанной ошибке; автоматический fallback в `review` при сбое **не реализован**. Тесты реального API находятся в `tests/test_api.py`, `tests/test_model_api_e2e.py` и других файлах; зелёный результат CI последнего коммита требуется проверить отдельно.

## CI и сдача
GitHub Actions содержит запуск pytest, сборку Docker и проверку Compose. Для официальной сдачи методичка просит личную ссылку на Colab, скриншот/текст pytest и вывод. Наличие кода в репозитории не подтверждает отправку.

## Вывод
Mock изолирует логику сервиса от случайных изменений модели; unit-тесты ловят ошибки препроцессинга. Они **не** заменяют проверку реального модельного артефакта, отказоустойчивости HTTP и качества антифрода.
