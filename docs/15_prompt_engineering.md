## Решение и тесты
```python
from experiments.webinar15_pairs import find_pairs
assert find_pairs([1,2,3,4,5],6)==[(1,5),(2,4)]
assert find_pairs([],6)==[]
assert find_pairs([3,3],6)==[(3,3)]
```
Алгоритм проходит вход за O(n) ожидаемо, но **итоговая сортировка** уникальных пар стоит O(k log k), где k — число пар. Поэтому полная функция — **O(n + k log k)**, а не строго O(n). Это осознанный компромисс ради детерминированного порядка; для строгого O(n) следует возвращать множество пар без сортировки. Тесты добавлены, но их исполнение в CI нового коммита нужно подтвердить.

## Правила безопасного использования ИИ (по практике)
1. Уточняю контракт до генерации: что считать дубликатом и что делать с крайними случаями.
2. Проверяю примеры вручную и через pytest, включая пустые входы, отрицательные числа и повторы.
3. Не доверяю заявленной сложности: учитываю стоимость сортировки, памяти и преобразований.
4. Проверяю используемые библиотеки, версии API и происхождение заимствованных фрагментов.
5. Не передаю реальные банковские данные, секреты и идентификаторы внешнему ассистенту.
