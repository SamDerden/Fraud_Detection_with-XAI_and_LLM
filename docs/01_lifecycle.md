# Вебинар 1 — жизненный цикл ИИ-системы: банковский антифрод

> **Основание:** лекция «Роль ИИ-инженера и ЖЦ ИИ-систем» и проектный кейс. Отдельная точная инструкция практики В01 среди доступных материалов не найдена; это оформленный проектный отчёт, а не подтверждение сдачи по неизвестному шаблону.

## Кейс и бизнес-цель
Учебный сервис оценивает риск мошенничества банковской транзакции и предоставляет оператору объяснение. Цель реального продукта — снизить финансовые потери, не увеличивая необоснованные ограничения для добросовестных клиентов. **Текущая реализация — демонстрация на синтетических данных; автоматическая банковская блокировка не реализована.**

**Пользователи:** банковский платёжный шлюз (машинный клиент API), аналитик антифрода (получатель объяснения), MLOps-инженер (эксплуатация). Банк и клиентские данные в проекте отсутствуют.

## ML-задача и критерии
Бинарная классификация `is_fraud` на исторических транзакциях; выход модели — score для приоритизации ручной проверки. Главная офлайн-метрика — **PR-AUC** при дисбалансе; дополнительные — recall, precision, FPR, ROC-AUC, матрица ошибок, p95 latency. Порог подбирается на validation, test сохраняется для независимой оценки. Score не является калиброванной вероятностью реального фрода.

## Жизненный цикл: результат, роль, риск и текущее состояние

| Этап | Действие и результат | Ответственный | Риск | Состояние |
|---|---|---|---|---|
| 1. Постановка | Определить бизнес-цену FN/FP, сценарий ручной проверки | Заказчик, аналитик | Ложные блокировки и потери | Учебная постановка готова; цены ошибок не согласованы с банком |
| 2. Сбор данных | Синтетические транзакции и исторические признаки | Data Engineer | Нереалистичная генерация, утечка будущего | v3: 7 000 размеченных + 3 776 warm-up |
| 3. Контроль качества | Проверить пропуски, идентификаторы, временную логику | Data Engineer, ML Engineer | Неконсистентные агрегаты | Первичный и статистический аудит проведены |

| 5. Эксперименты | Сравнить RF, CatBoost, LightGBM, ансамбль | Data Scientist | Выбор по test | Диагностическое сравнение есть; MLflow для v3 не подтверждён |
| 6. Тестирование | Проверить контракт, устойчивость, ошибки, SHAP | ML/QA Engineer | Некорректные решения | Есть pytest; окончательный E2E v3 не подтверждён |
| 7. Поставка | Упаковать модель и API в Docker | MLOps Engineer | Сбой и несовместимость артефакта | Docker/Compose в репозитории; production не развёрнут |
| 8. Мониторинг | Логи, Prometheus, дрейф и качество по отложенным меткам | MLOps, аналитик | Незамеченная деградация | Метрики HTTP реализованы; качество на реальном потоке не измеряется |
| 9. Обновление | Аудит новых данных → эксперименты → shadow/canary → откат | ML/MLOps | Регрессия качества | Только стратегия; реального shadow/canary нет |

## Архитектурное ограничение и границы безопасности
Путь текущего демонстрационного API: запрос → FastAPI/Pydantic → CatBoost-артефакт **при наличии `ANTIFRAUD_MODEL_DIR`** → SHAP → опциональный LLM → ответ. Без артефакта используется отдельно помеченная синтетическая RandomForest-демонстрация. В режиме артефакта решение ограничено `approve/review`; автоматической блокировки нет. Модель v3 пока не выбрана как итоговая по результатам validation.

## Актуализация выбора модели — ExtraTrees v4 (21.11.2026)

**Для защиты выбрана ExtraTrees v4**, 13 исходных + 7 производных признаков; validation PR-AUC **0,342852**, ROC-AUC **0,803479** на синтетическом v3. В 32-конфигурационном скрининге это лучший validation PR-AUC. Параметры: `n_estimators=200, max_depth=4, min_samples_leaf=6, random_state=42`. Артефакт [extratrees-v4-artifact.zip](../extratrees-v4-artifact.zip) опубликован. [Методика, все 32 результата и ограничения](WEBINAR05_32_EXPERIMENTS.md). **Сервер и XAI пока работают по legacy-контракту; v4 ещё не подключена.** Упоминания CatBoost/Blend выше относятся к предыдущему этапу проекта, не к финальному выбору. Отдельный test для v4 и калибровка порога не подтверждены.
