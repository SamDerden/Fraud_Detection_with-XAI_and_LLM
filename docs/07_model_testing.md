# Вебинар 7 — качество и тестирование модели на v3

**Данные:** только принятый v3, 7 000 синтетических транзакций; train 5 000 / validation 1 000 / test 1 000. Исходный проблемный CSV из вебинара 6 здесь не используется.

## Требования методички
Проверить модель и получить Accuracy/F1; составить тест-план из пяти типов, написать минимум пять pytest-тестов, выполнить их, заполнить таблицу PASSED/FAILED с пояснениями и сформулировать вывод. Методичка демонстрирует текстовую модель; мы адаптировали проверяемые свойства к табличному антифроду.

## Тест-план и фактические результаты
| Тип проверки | Что проверяется | Результат локального запуска |
|---|---|---|
| Функциональная | `predict_proba` возвращает 1 000 значений в [0,1] | PASS |
| Качество | Validation PR-AUC RandomForest выше базовой частоты класса | PASS |
| Стабильность | Повторный вызов даёт идентичные оценки | PASS |
| Границы | Все суммы транзакций положительны | PASS |
| Корректность данных | 7-дневные счётчики согласованы с 24-часовыми и количеством мерчантов | PASS |
| Метрики | Accuracy/F1 вычисляются и лежат в [0,1] | PASS |

**Подтверждение:** `ANTIFRAUD_V3_CSV=/mnt/data/antifraud_v3/transactions_v3.csv pytest -q tests/test_webinar07_quality.py` → **6 passed** (локальная среда 20.11.2026). Тесты загружают v3 из переменной окружения; без файла **skip**, а не ложный PASS. Они не являются проверкой банковского качества.

## Диагностический тест четырёх моделей
| Модель | PR-AUC validation | PR-AUC test | Recall test | FPR test |
|---|---:|---:|---:|---:|
| RF | 0.25328 | 0.22334 | 40.68% | 10.63% |
| CatBoost | 0.24352 | 0.21451 | 38.98% | 10.63% |
| LightGBM | 0.20174 | **0.25524** | 38.98% | **9.88%** |
| Blend | **0.25779** | 0.22161 | **42.37%** | 10.31% |

Test содержит 59 мошеннических операций. У Blend TP=25, FN=34; это недостаточно для реального антифрода. Пороги и вес Blend выбирались только на validation. Выбор модели **не** должен основываться на лучшем test PR-AUC. Сильная корреляция признака нового устройства с синтетической меткой и отсутствие новых пользователей в test — ограничения генератора.

## Вывод
Тестируемость и базовые свойства модели подтверждены локально; бизнес-готовность — **нет**. Отдельно необходимо подтвердить модельный E2E в API и результаты GitHub CI. Исторические метрики прежнего датасета (ROC-AUC ~0.94, F1 ~0.70) не относятся к v3.


## Актуальная модель для защиты: ExtraTrees v4

Выбрана **ExtraTrees v4 (200 деревьев, max_depth=4, min_samples_leaf=6)** с 13 исходными и 7 производными признаками: validation PR-AUC **0,342852**, ROC-AUC **0,803479**. Основание — лучший результат из [32 сравнительных конфигураций](WEBINAR05_32_EXPERIMENTS.md), с оговоркой о неодинаковом бюджете Optuna и отсутствии новой независимой test-оценки. [ZIP артефакта](../extratrees-v4-artifact.zip) уже в репозитории. **В коде FastAPI и тестах пока используется legacy CatBoost/Blend или учебный fallback; E2E v4 ещё не подтверждён.** Старые метрики в документе сохранены как исторические, не как показатели выбранной модели.
