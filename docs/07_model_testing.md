## Актуальная тестовая стратегия
`tests/test_behavior.py`, `tests/test_quality_drift.py`, `tests/test_artifact.py` и `tests/test_api.py` проверяют вероятности, крайние значения, API-контракт, ошибки входных данных, качество датасета и схему модели. `experiments/compare_four_models.py` фиксирует PR-AUC, ROC-AUC, precision, recall, FPR и confusion matrix на отдельном хронологическом тесте. Ранее опубликованные учебные метрики (например recall 0.5714) **не являются оценкой новой модели на 5 000 транзакций**.


## Дополнительный аудит качества (20.11.2026)
На предоставленном CSV обнаружено 897 строк, где `tx_count_7d < tx_count_24h`. При одинаковой семантике окон это неконсистентно и требует проверки генерации признаков. 634 пользователя встречаются одновременно в обучающем (первые 60%) и тестовом (последние 20%) периодах: это допустимо для временной оценки повторных клиентов, но не измеряет переносимость на полностью новых пользователей. Исторические агрегаты нельзя независимо восстановить из плоского CSV, поэтому отсутствие утечки не доказано.

Для сохранённого CatBoost: при ограничении FPR 10% **на валидации** порог 0.2540 даёт на тесте Recall 31.06%, FPR 12.51%, 155 отправленных на review из 1000. При ограничении FPR 3% на валидации порог 0.3765 даёт на тесте Recall 16.77%, FPR 4.29%, 63 отправленных на review. Порог не подбирался по тесту; таблица сценариев находится в `experiments/audit_features_thresholds.py`. Обе настройки недостаточны для реального банковского антифрода.
